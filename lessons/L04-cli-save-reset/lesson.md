## ۱. خوشامدگویی

سلام و خوش اومدی به درس چهارم.

تا اینجا یاد گرفتی با دستگاه «حرف بزنی»، بین اتاق‌ها بروی و با دستورهای «نشونم بده» بپرسی. امروز اولین بار
**واقعاً چیزی رو توی دستگاه عوض می‌کنی** و بعد یاد می‌گیری سه کار حیاتی رو انجام بدی:

1. تنظیم رو **ذخیره کنی** تا با خاموش و روشن شدن از بین نره؛
2. هر تنظیم رو **برعکس کنی**؛
3. بفهمی دستگاه دو نسخه از تنظیمات داره و **تفاوتشون** رو پیدا کنی.

مثال روزمره: فکر کن توی کلاس، روی **تخته سیاه** یه برنامه نوشتی و بعد از ظهر خدمتکار تخته رو پاک می‌کنه.
اگه برنامه رو توی **دفتر ثبت** هم نوشته بودی، چیزی از دست نرفته. تخته همون «تنظیمات زنده» است و دفتر ثبت همون
«تنظیمات ذخیره‌شده».

## ۲. اهداف قابل سنجش

بعد از این درس، هنرجو می‌تواند:

1. تفاوت «تنظیمات زنده» و «تنظیمات ذخیره‌شده» را با زبان خودش و با نمودار توضیح دهد؛
2. روی یک دستگاه خام، اسم، پیام خوش‌آمد، گذرواژه مدیر و گذرواژه کنسول را بگذارد؛
3. روی یک درگاه، توضیح بنویسد و آن را روشن کند؛
4. تنظیمات را به سه شکل ذخیره کند و اثبات کند ذخیره شده است؛
5. برای هر دستور تنظیم، دستور «برعکس» را بنویسد؛
6. معنی پیشوند «دو» را بفهمد و فقط در اتاق درست از آن استفاده کند؛
7. دستگاه را با هشدار و نسخه پشتیبان پاک و دوباره راه‌اندازی کند؛
8. دو نسخه تنظیمات را بخواند و تفاوتشان را پیدا کند.

## ۶. آموزش مفهومی با نمودار

### ۶.۱ دو حافظه، دو نسخه

**مثال روزمره:** تخته سیاه و دفتر ثبت.

**تعریف ساده:** دستگاه همیشه دو نسخه از تنظیمات دارد.

- نسخه زنده: همان چیزی که دستگاه الان طبق آن کار می‌کند. در حافظه رم است. **با خاموشی پاک می‌شود.**
- نسخه ذخیره‌شده: دفتر ثبت. در حافظه ان‌وی‌رم است. **با خاموشی می‌ماند.** دستگاه موقع روشن شدن آن را می‌خواند.

**چرا مهم است:** هر دستور تنظیمی که می‌زنی، **فوراً** روی نسخه زنده اثر می‌گذارد، ولی نسخه ذخیره‌شده را **خودش عوض
نمی‌کند**. یعنی اگر ذخیره نکنی، با اولین قطع برق همه زحمتت برباد می‌رود.

**اگر اشتباه باشد چه می‌شود:** دستگاه بعد از روشن شدن مثل روز اول برمی‌گردد (اسم پیش‌فرض، بدون گذرواژه).

**در شبکه واقعی:** معروف‌ترین ماجرای «دیروز کار می‌کرد، امروز نه!» همین است: کسی تنظیم را زد، کار کرد، ذخیره
نکرد، برق رفت.

``` mermaid
flowchart LR
    K["شما دستور می‌زنید"] --> R["حافظه موقت رم<br/>running-config<br/>تنظیمات زنده"]
    R -- "خاموشی" --> X["پاک می‌شود"]
    R -- "ذخیره کردن" --> N["حافظه دائمی ان‌وی‌رم<br/>startup-config<br/>تنظیمات ذخیره‌شده"]
    N -- "روشن شدن دوباره" --> R
```

**مثال آزمایشگاهی:** اسم سوییچ را عوض می‌کنی؛ علامت جلوی خط فوراً عوض می‌شود (نسخه زنده). اما اگر همین الان سوییچ را
خاموش و روشن کنی، دوباره اسم قدیمی برمی‌گردد.

**جمع‌بندی یک‌دقیقه‌ای:** تنظیم می‌زنی ← روی تخته می‌نویسد؛ ذخیره می‌کنی ← توی دفتر ثبت می‌نویسد؛ روشن می‌شود ← از روی
دفتر ثبت می‌خواند و روی تخته می‌نویسد.

### ۶.۲ سه روش ذخیره، یک کار

سه دستور داریم که **هر سه یک کار** را می‌کنند: «از زنده بردار، روی ذخیره‌شده بنویس».

``` mermaid
flowchart TD
    A["شکل کامل<br/>copy running-config startup-config"] --> D["تنظیمات زنده روی حافظه دائمی نوشته می‌شود"]
    B["شکل کوتاه<br/>write memory یا write"] --> D
    C["از اتاق تنظیمات<br/>do write"] --> D
```

نکته مهم: «دو» جای شما را **عوض نمی‌کند**. بعد از ذخیره با شکل «دو»، هنوز همان‌جا که بودی ایستاده‌ای.

### ۶.۳ اتاق‌ها و پیشوند «دو»

پیشوند «دو» یعنی: «من توی اتاق تنظیمات ایستاده‌ام ولی یه کار مخصوص اتاق مدیر دارم؛ برو انجامش بده و برگرد». این
پیشوند **فقط داخل اتاق‌های تنظیمات** معنی دارد.

| اتاق | نشانه جلوی خط (نمونه) |
|---|---|
| عادی | `Switch>` |
| مدیر | `Switch#` |
| تنظیمات | `Switch(config)#` |
| درگاه | `Switch(config-if)#` |
| خط کنسول | `Switch(config-line)#` |

``` mermaid
flowchart LR
    C["شما در اتاق تنظیمات ایستاده‌اید"] -- "do write" --> B["کار مخصوص اتاق مدیر انجام می‌شود"]
    B -- "نتیجه برمی‌گردد" --> C
```

### ۶.۴ پیشوند «نو»

پیشوند «نو» یعنی «برعکسش کن». هر تنظیمی که با یک دستور اضافه می‌کنی، با همان دستور و یک «نو» جلویش برداشته می‌شود.

``` mermaid
flowchart LR
    S["تنظیم: hostname SW1"] -- "no hostname" --> D["برگشت به اسم پیش‌فرض"]
    S2["تنظیم: shutdown"] -- "no shutdown" --> E["روشن"]
```

**دو تله مهم:**

1. «نو» روی **تنظیم** کار می‌کند، نه روی **کار**. ذخیره کردن یک «کار» است؛ برعکس ندارد.
2. «نو» فقط نسخه **زنده** را عوض می‌کند. اگر قبلاً ذخیره کرده باشی، باید بعد از «نو»، دوباره ذخیره کنی.

### ۶.۵ پاک کردن و راه‌اندازی دوباره

``` mermaid
flowchart TD
    A["هشدار: فقط روی دستگاه آزمایشگاهی"] --> B["نسخه پشتیبان از فایل و از خروجی تنظیمات"]
    B --> C["پاک کردن تنظیمات ذخیره‌شده"]
    C --> D["راه‌اندازی دوباره"]
    D --> E["دستگاه با اسم و تنظیمات پیش‌فرض بالا می‌آید"]
```

## ۷. درس زبان فرمان: جمله‌ها، تجزیه و گفتگوی انسانی

هر دستور جدید با هفت مرحله می‌آید: ۱. جمله انسانی؛ ۲. تجزیه؛ ۳. اتاق؛ ۴. گفتگو؛ ۵. برعکس؛ ۶. خطا؛ ۷. کوتاه‌شده.
اسم‌ها و گذرواژه‌های مثال‌های آموزشی (مثل اسم دستگاه و برچسبی که در مثال‌ها می‌بینی) با اسم‌ها و داده‌های تمرین‌ها فرق دارند.

### ۷.۱ اسم دستگاه

``` text
hostname SW1
```

۱. **جمله انسانی:** «اسمت رو بذار این.»

۲. **تجزیه:**

``` text
hostname    = اسم دستگاه
SW1         = اسمی که می‌خوام بذاری
```

۳. **اتاق:** تنظیمات.

۴. **گفتگو:**

``` text
شما:      hostname SW1
دستگاه:   «hostname» یعنی اسم دستگاه. اسم جدید رو هم شنیدم.
          (هیچ پیامی نمی‌دم؛ فقط علامت جلوی خط عوض می‌شه.)
```

۵. **برعکس:**

``` text
no hostname
```

۶. **خطا:** اگر اسم را ننویسی، پیام «جمله‌ات ناقصه» می‌آید:

``` text
% Incomplete command.
```

اگر اسم فاصله داشته باشد، پیام «این کلمه رو نمی‌فهمم» می‌آید.

۷. **کوتاه‌شده:** این دستور کوتاه‌شده ندارد؛ اسم‌ها را کامل بنویس.

### ۷.۲ پیام خوش‌آمد

``` text
banner motd #Authorized access only#
```

۱. **جمله انسانی:** «هر کس اومد پشت دستگاه، این پیام رو بهش نشون بده.»

۲. **تجزیه:**

``` text
banner        = پیام خوش‌آمد (تابلو)
motd          = پیام روز (موقع ورود نشون داده می‌شه)
#             = نویسه مرزبند: شروع پیام
Authorized access only = متن پیام
#             = نویسه مرزبند: پایان پیام
```

۳. **اتاق:** تنظیمات.

۴. **گفتگو:**

``` text
شما:      banner motd #Authorized access only#
دستگاه:   «#» رو به‌عنوان مرز می‌شناسم. هر چی بین دو تا «#» باشه، پیامه.
          حواست باشه خود متن پیام نباید «#» داشته باشه، وگرنه فکر می‌کنم پیام تموم شده.
```

۵. **برعکس:**

``` text
no banner motd
```

۶. **خطا:** اگر نویسه مرزبند را داخل متن بیاوری، دستگاه فکر می‌کند پیام همان‌جا تمام شده. (رفتار دقیق: نیازمند
راستی‌آزمایی در نسخه نصب‌شده.)

۷. **کوتاه‌شده:** ندارد؛ فقط نویسه مرزبند دلخواه است (مثلاً به‌جای علامت شارپ می‌توان از علامت دلار استفاده کرد).

### ۷.۳ گذرواژه اتاق مدیر

``` text
enable secret <password>
```

۱. **جمله انسانی:** «برای ورود به اتاق مدیر، این گذرواژه رو ازم بپرس.»

۲. **تجزیه:**

``` text
enable    = اتاق مدیر
secret    = مخفی (طوری ذخیره کن که توی تنظیمات خوانا نباشه)
<password> = گذرواژه
```

۳. **اتاق:** تنظیمات.

۴. **گفتگو:**

``` text
شما:      enable secret <password>
دستگاه:   گذرواژه رو گرفتم. از این به بعد قبل از اینکه کسی بره اتاق مدیر، ازش می‌پرسم.
          خودِ گذرواژه رو توی تنظیمات به‌صورت درهم‌شده می‌نویسم.
```

۵. **برعکس:**

``` text
no enable secret
```

۶. **خطا:** اگر گذرواژه ننویسی:

``` text
% Incomplete command.
```

۷. **کوتاه‌شده** (فقط وقتی شکل کامل را یاد گرفته‌ای):

``` text
ena sec
```

### ۷.۴ ورود به تنظیمات خط کنسول

``` text
line console 0
```

۱. **جمله انسانی:** «برو به تنظیمات ورودی کابل کنسول.»

۲. **تجزیه:**

``` text
line      = خط (راه ورود به دستگاه)
console   = کنسول (ورودی کابل مخصوص)
0         = شماره خط (اولین و تنها خط کنسول)
```

۳. **اتاق:** تنظیمات. بعد از دستور، وارد اتاق **خط کنسول** می‌شوی.

۴. **گفتگو:**

``` text
شما:      line console 0
دستگاه:   باشه، رفتیم به اتاق «خط کنسول». هر چی بگی، مربوط به همین ورودیه.
          (علامت جلوی خط می‌شه: config-line)
```

۵. **برعکس:** این دستور فقط «رفتن به اتاق» است. برگشت:

``` text
exit
```

۶. **خطا:** شماره‌ای غیر از صفر معمولاً مجاز نیست:

``` text
% Invalid input detected at '^' marker.
```

۷. **کوتاه‌شده:**:

``` text
line con 0
```

### ۷.۵ گذرواژه کنسول (داخل خط کنسول)

``` text
password <password>
```

۱. **جمله انسانی:** «گذرواژه این ورودی رو این بذار.»

۲. **تجزیه:**

``` text
password   = گذرواژه
<password> = خود گذرواژه
```

۳. **اتاق:** خط کنسول.

۴. **گفتگو:**

``` text
شما:      password <password>
```

> (متن دقیق پیام‌ها: نیازمند راستی‌آزمایی در نسخه نصب‌شده.)

## ۱۰. سه زاویه و نگاه فرمان

**الف) من به دستگاه چی می‌گم؟** «تنظیمات زنده را روی تنظیمات ذخیره‌شده بنویس»، چون تنظیمات زنده با قطع برق از بین می‌رود.

**ب) دستگاه حرف من رو چطور می‌فهمه؟** مفسر خط فرمان کلمه به کلمه جمله را تجزیه می‌کند، می‌بیند «کپی» است، مبدأ را از حافظه
رم برمی‌دارد، آن را در ان‌وی‌رم می‌نویسد و پیام «انجام شد» می‌دهد.

**ج) در نهایت چه اتفاقی می‌افته؟** حالا هر دو نسخه یکی هستند. با دستور نمایش تنظیمات ذخیره‌شده می‌توانی ببینی. خاموش و روشن شدن
چیزی را از بین نمی‌برد.

**نگاه فرمان** (در این درس بسته‌ای بین دو دستگاه عوض نمی‌شود؛ به جای نگاه بسته، مسیر دستور را ببین):

``` mermaid
flowchart LR
    A["شما تایپ می‌کنید"] --> B["مفسر دستور<br/>می‌فهمد کدام اتاق، کدام فعل"]
    B --> C["تغییر در حافظه رم"]
    C -- "فقط اگر ذخیره کنید" --> D["نوشتن در حافظه دائمی"]
```

### ۱۲.۲ «دو» در اتاق اشتباه

| وضعیت | چه می‌شود | درمان |
|---|---|---|
| در اتاق مدیر دستور «دو» را زدی | پیام «این کلمه رو نمی‌فهمم» | «دو» را حذف کن؛ فقط دستور اتاق مدیر را بزن |

### ۱۲.۳ تفاوت دو نسخه تنظیمات

روش کار: هر دو خروجی را بخوان و در دو ستون کنار هم بنویس. سه نوع تفاوت را دنبال کن:

1. **خطی که فقط در نسخه زنده هست:** ذخیره نشده؛ با قطع برق از بین می‌رود.
2. **خطی که فقط در نسخه ذخیره‌شده هست:** در نسخه زنده برداشته شده؛ با ذخیره کردن از دفتر هم پاک می‌شود.
3. **خطی که در هر دو هست ولی مقدار فرق دارد:** نسخه زنده برنده است؛ اگر ذخیره کنی، جای قدیمی را می‌گیرد.

### ۱۲.۴ روش‌های بازگردانی

| می‌خواهم | روش |
|---|---|
| یک تنظیم را برگردانم | همان دستور با پیشوند «نو»، سپس ذخیره |
| همه تغییرهای ذخیره‌نشده را دور بریزم | (فقط در آزمایشگاه) راه‌اندازی دوباره و جواب «نه» به سؤال ذخیره |
| به حالت کارخانه برگردم | پاک کردن تنظیمات ذخیره‌شده و راه‌اندازی دوباره، با هشدار و نسخه پشتیبان |
| به وضعیت قبل از درس برگردم | باز کردن نسخه قبلی فایل آزمایشگاه |

## ۱۳. نکته امنیتی

این درس امنیتی نیست و هشدار ثابت لازم ندارد؛ اما چند اصل را از همین‌جا شروع کن:

- **فقط مفهوم:** گذرواژه کنسول در تنظیمات زنده **خوانا** نوشته می‌شود. گذرواژه مدیر که با «سیکرت» گذاشته شود،
  **درهم‌شده** نوشته می‌شود و کسی نمی‌تواند مستقیم آن را بخواند. پنهان کردن همه رمزها در درس ۲۸ می‌آید.
- هر خروجی تنظیمات که برای گزارش، چت یا مخزن می‌فرستی، ابتدا بخوان که گذرواژه واقعی در آن نباشد.
- در آزمایشگاه فقط گذرواژه ساختگی بگذار.
- پیام خوش‌آمد، هشدار ورود است نه خوش‌آمدگویی؛ کوتاه و بدون اطلاعات دستگاه بنویس.
- پاک کردن و راه‌اندازی دوباره فقط روی دستگاهی که مالکش خودت هستی.

``` mermaid
flowchart LR
    A["گذرواژه کنسول<br/>password"] --> B["در تنظیمات زنده خوانا"]
    C["گذرواژه مدیر<br/>enable secret"] --> D["در تنظیمات زنده درهم‌شده"]
    B --> E["هر کس تنظیمات را ببیند، می‌خواند"]
    D --> F["خواندن مستقیم ممکن نیست"]
```

- وجود پیشوند «نو» برای برگرداندن تنظیم؛ ولی ذخیره‌کردن، تنظیم نیست و «نو» ندارد.
- «دو» فقط داخل اتاق‌های تنظیمات کار می‌کند.
- گذرواژه با «سیکرت» در تنظیمات پنهان می‌شود؛ گذرواژه کنسول خوانا است (جزئیات در درس ۲۸).
- حواست به تله‌های «ذخیره نشد و برق رفت» و «اسم عوض شد ولی ذخیره‌شده فرق دارد» باشد.

---

## ۱۹. جمع‌بندی

- دستگاه دو نسخه تنظیمات دارد: زنده (تخته) و ذخیره‌شده (دفتر ثبت).
- هر تنظیم فوراً روی نسخه زنده اثر می‌گذارد؛ ذخیره‌شدن، یک کار جداست.
- سه روش ذخیره یک کار را می‌کنند: شکل کامل، شکل کوتاه، «دو» در اتاق تنظیمات.
- «نو» تنظیم را برمی‌گرداند؛ «دو» دستور اتاق مدیر را در اتاق تنظیمات صدا می‌زند.
- پاک‌کردن و راه‌اندازی دوباره فقط با هشدار و نسخه پشتیبان.
- قانون طلایی: بعد از هر تغییر، ذخیره کن و دوباره بپرس.

---

## ۲۰. معیار آمادگی برای درس بعد

هنرجو آماده است اگر **بدون نگاه به جزوه** بتواند:

- [ ] یک دستگاه خام را نام‌گذاری و پایه‌ایمن کند؛
- [ ] ذخیره کند و با نگاه به تنظیمات ذخیره‌شده اثبات کند؛
- [ ] هر تنظیم را با «نو» برگرداند و بداند کدام کار «نو» ندارد؛
- [ ] از «دو» در اتاق درست استفاده کند؛
- [ ] دو نسخه تنظیمات را بخواند و تفاوتشان را بگوید؛
- [ ] دفترچه آزمایش را بنویسد.

**درس بعد:** L05 (طبق نقشه راه).
